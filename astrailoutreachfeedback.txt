I'd say the cost grows less with the number of APIs and more with the number and complexity of integrations. One clean integration can be easy, but each additional system brings its own auth flows, rate limits, field mapping, error formats, retries, permissions, versioning and monitoring. The real cost is often not just building the connector, but maintaining and debugging all the customer-specific edge cases around it.

A third of engineering time is not crazy if “integration” includes all the glue around the API, not just writing the connector.
The expensive parts are usually:
auth and token refresh edge cases
field mapping when the customer’s CRM is weird
rate limits, retries, and partial failures
webhook idempotency so one event does not create two actions
permissions: what the agent can read, draft, write, or send
audit logs a human can understand later
migration when the customer changes tools or schema
The number worth measuring is not just connector build time. Track integration work as setup, maintenance, support/debugging, and customer-specific exceptions. Those are different cost centers.
A clean rule of thumb: if every new customer needs custom mapping, custom auth handling, or custom approval logic, you do not have an agent product yet. You have a services business with an agent inside it. That can still be a good business, but the margin math is totally different.
